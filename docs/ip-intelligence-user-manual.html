IP Intelligence User Manual

How to find out where an IP address is and whether it is a proxy, VPN, Tor exit or bot, from the app, the API or Athena, and how to keep the daily system running.

Addresses 4,956,914Updated daily 07:30 UTCproxycheck.io 80,000 queries/day

Start here

Every IP address seen in the ad-click and website-session tables has a location and a proxy verdict. Pick whichever of these suits the job.

The app (Lovable)

Type one address, or paste up to 1,000, and read the answer. Best for looking something up, and for running the pipeline.

The API

GET /lookup/{ip} or POST /lookup for up to 1,000. Best for other systems and scripts. Asks proxycheck.io on the spot when our tables have no conclusion.

Athena

Query ipintel_curated.ip_resolved: one row per address. Best for reports and joining to other data. Never spends proxycheck.io queries.

The one table most people needipintel_curated.ip_resolved holds the answer to use for every address: location, proxy verdict, the vendors it rests on, and where the address was seen. The other tables hold each vendor's own answer and the working behind the verdicts.

Reading an answer

Each answer has a location part and a proxy part, and each part has a status that says how sure it is.

Location status

StatusMeaningHow much to trust it
agreedTwo or more vendors name the same state and cityStrongest
single_sourceOnly one vendor answered, almost always IP2LocationState is usually right; treat city as approximate
vendors_disagreeVendors name different places; the best-scoring vendor's answer is shownMostly the same state and a nearby city
no_answerNo vendor has a location—
An IP location is not a home addressIt places the network hub. City matches a customer's own postal address only 10–15% of the time, and state about 55–60%, for every vendor (see Reports · Location Accuracy). Use it for regional analysis, never as a person's address.

Proxy status

StatusMeaningflagged
confirmedproxycheck.io answered and at least one other vendor agreestrue or false
proxycheck_onlyproxycheck.io is the only vendor that answeredtrue or false
proxycheck_overridesproxycheck.io answered the opposite of every other vendor, and its answer is usedtrue or false
clean_by_vendorsNo proxycheck.io answer; every vendor that answered says cleanfalse
flagged_unconfirmedA vendor flags it and nothing confirms the flagempty
vendors_disagreeVendors disagree and proxycheck.io has not answered yetempty
no_answerNo vendor gave a proxy answerempty

Empty means "no conclusion", never "clean". Every yes/no field has three states: true, false, and empty (no answer). Treating empty as false is the most common mistake; in SQL, WHERE NOT flagged silently drops the empty rows, so write WHERE flagged = false or WHERE flagged IS NULL on purpose.

The flags

is_proxy, is_vpn, is_tor, is_datacenter, is_bot, is_compromised, is_scraper, is_anonymous. flagged is true when any of the first seven is true. Two things to know:

  • proxycheck.io labels most datacenter traffic as VPN. For "not an ordinary home connection" use is_vpn OR is_proxy OR is_datacenter.
  • Only FraudLogix answers is_bot. No bot flag is confirmed by a second vendor.
  • Many of the busiest VPN-flagged addresses are Cloudflare and Apple privacy relays used by ordinary people. Judge them on behaviour, not the flag alone.

Reading the Location Accuracy report

The truth is the postal address of 2,105 qualified customers (full state name and 5-digit ZIP). For each vendor, and for Our answer (resolved), the report counts how often the IP location matches:

  • State: the same state name, ignoring case.
  • City: the same city name, letters only, ignoring case. This is stricter than the vendor vote, which compares only the first word of the city.
  • ZIP: the same first five digits.
  • State + city: both match.

Two pools are shown. Every address each vendor answered gives each vendor as many tests as it can take. Same addresses uses only the 1,049 addresses every location vendor answered, so the vendors are compared on equal terms. The by-state table marks states with fewer than 20 tested addresses as a small sample.

No vendor reaches 100%, and that is expectedA postal address is where the customer lives, not always where the connection is (mobile carriers, work networks). Use the numbers to compare vendors with each other, not as the chance a single answer is right.

Accuracy and agreement are different. "Agreement" on the vendor scorecards means how often a vendor matches the other vendors. "Accuracy" means how often a vendor matches customers' postal addresses, and is used only on the Location Accuracy page.

Paging. limit is 2,000 by default and at most 5,000. For the next page pass the next_cursor and query_id from the response (fast, no new scan); offset also works up to 100,000. Many IPs at once

POST /lookup answers up to 1,000 addresses in one call, usually within 20–40 seconds, with the same answers as one-at-a-time lookups.

curl -X POST -H "Authorization: Bearer YOUR_API_TOKEN" -H "content-type: application/json" \
  -d '{"ips": ["8.8.8.8", "152.232.101.74", "10.0.0.1"]}' \
  "https://h25l6d2efgqnxqjrt6xpzjzbdq0hceyr.lambda-url.us-west-2.on.aws/lookup"
Body fieldDefaultMeaning
ipsrequired1 to 1,000 IPv4 addresses; duplicates are merged
proxychecktruefalse answers from the tables only and never spends a query
refreshfalsetrue asks proxycheck.io again for every public address (about one query each)
detail"summary""full" also returns every vendor's rows and the occurrences

Addresses that need proxycheck.io go to it together in one request. The response has a proxycheck summary (needed, asked, answered, queries reserved, any error) and one results entry per address with resolved and proxycheck like a single lookup.

A whole list, in Python

import csv, json, os, urllib.request

URL = "https://h25l6d2efgqnxqjrt6xpzjzbdq0hceyr.lambda-url.us-west-2.on.aws/lookup"
TOKEN = os.environ["IPINTEL_API_TOKEN"]          # never paste the token into the script

ips = [line.strip() for line in open("ips.txt") if line.strip()]
rows = []
for i in range(0, len(ips), 1000):               # 1,000 per request
    body = json.dumps({"ips": ips[i:i + 1000], "proxycheck": True}).encode()
    req = urllib.request.Request(URL, data=body, method="POST",
                                 headers={"Authorization": "Bearer " + TOKEN, "content-type": "application/json"})
    reply = json.loads(urllib.request.urlopen(req, timeout=120).read())
    if reply["proxycheck"]["error"]:
        print("note:", reply["proxycheck"]["error"])
    for r in reply["results"]:
        g, p = r["resolved"]["geo"], r["resolved"]["proxy"]
        rows.append([r["ip"], g["state"], g["city"], g["zip_code"], g["status"],
                     p["flagged"], p["is_vpn"], p["is_proxy"], p["status"], p["isp"]])

with open("ip_answers.csv", "w", newline="") as f:
    csv.writer(f).writerows([["ip", "state", "city", "zip", "geo_status",
                              "flagged", "is_vpn", "is_proxy", "proxy_status", "isp"]] + rows)
Budget for bulk lookupsAPI lookups share the daily proxycheck.io limit with the pipeline. 30,000 queries a day are always kept free for lookups, all day and after the 22:00 UTC top-up; the pipeline never spends them. When the limit is reached, the call still answers from the tables and says so in proxycheck.error. For lists of addresses that are already in the tables, set "proxycheck": false or use Athena.

Using Athena

Everything is in the ipintel_curated database. Queries that filter on ip_address read only a few megabytes.

-- The answer for a list of addresses
SELECT ip_address, state, city, zip_code, geo_status, flagged, is_vpn, is_proxy, is_datacenter,
       proxy_status, isp, proxycheck_risk_score, last_seen
FROM ipintel_curated.ip_resolved
WHERE ip_address IN ('8.8.8.8', '152.232.101.74');

-- Join to your own data: sessions with the IP verdict
SELECT s.session_date, s.session_ip, r.state, r.flagged, r.proxy_status
FROM unified.unified_session_summary s
LEFT JOIN ipintel_curated.ip_resolved r ON r.ip_address = s.session_ip
WHERE s.session_date = date '2026-09-10';

-- Addresses with no conclusion yet
SELECT proxy_status, count(*) FROM ipintel_curated.ip_resolved
WHERE proxy_status IN ('no_answer', 'vendors_disagree', 'flagged_unconfirmed') GROUP BY 1;

All tables, and dozens more ready-made queries, are in ATHENA_REVIEW_QUERIES_LIVE.md in the project folder. Every timestamp is UTC as YYYY-MM-DDTHH:MM:SSZ.

Please use your own workgroup for readingThe ipintel and ipintel_etl workgroups belong to the API and the daily jobs. Reading the tables from your usual workgroup is fine; writing to ipintel_curated is reserved for the pipeline.

The unified copies. unified.ip_geo and unified.ip_intelligence are copies of the same tables in ipintel_curated, refreshed after each successful proxycheck.io run for another team's API. They can lag by up to a day and no longer hold the removed benchmark vendors. For your own queries, use ipintel_curated.

The proxycheck.io budget

The plan allows 80,000 queries a day. Since 15 Sep 13:00 UTC, at the owner's request, 50,000 go to enrichment and 30,000 are always kept free for API lookups. A shared counter reserves every query before it is sent, so nothing can go over the limit.

UseQueriesNotes
Enrichment: addresses from new base-table rows, then the daily backfillup to 50,000Queued addresses count inside the 50,000 and no longer borrow from the lookup reserve
API lookups (one or bulk)30,000 kept free1 query per address, 2 reserved for a single lookup; lookups can use anything left of the 80,000
22:00 top-uprest of the 50,000Only runs batches if the morning run stopped early; never touches the 30,000

What the backfill sends first

  1. Addresses queued from new base-table rows.
  2. Addresses first seen today.
  3. Every address seen in the base tables in the last 30 days that proxycheck.io has not answered, even if the other vendors agree it is clean. proxycheck.io confirms the proxy answer and adds a second vote on location.
  4. Addresses with no conclusion (no_answer, vendors_disagree, flagged_unconfirmed): seen in the last 90 days first, then by kind of no-conclusion and most recently seen.

For 16 Sep the backfill picked 49,504 addresses: the first 20,597 are every remaining address from the last 30 days (8,719 with no answer and 11,878 clean by vendors), then 28,907 older addresses with no answer, seen 31–90 days ago.

The Edit budget on Daily Jobs changes only the enrichment share, up to 50,000 (the 80,000 limit minus the 30,000 lookup reserve). An address that is both proxy and VPN is charged twice by proxycheck.io; about 1% extra is reserved for that. The proxycheck Budget page shows our counter and proxycheck.io's own, which runs a few minutes behind.

Common tasks

Stop everything now

  1. Open Safety and press Pause everything.
  2. Give a reason. Both jobs and every proxycheck.io call stop; nothing is deleted.
  3. Press Resume when ready. Resume is refused while a safety check is failing.

Collect addresses from another table

  1. Open Base Tables and press Add base table.
  2. Pick the database, table, IP column and seen-at column from the lists.
  3. Save. The table is checked immediately; fix anything listed under problems. The next daily load reads it. The pipeline only reads base tables, never writes to them.

Get today's new addresses in now instead of tomorrow

  1. Open Daily Jobs and press Run now on Free sources.
  2. When it finishes it starts the proxycheck job for any addresses that need it.

Change how much the backfill spends

  1. Open Daily Jobs, proxycheck card, Edit the daily budget (at most 50,000; the other 30,000 stay free for lookups).

Check whether the last 30 days are enriched

  1. Open Reports · Enrichment Coverage (or call GET /coverage).
  2. In the last-30-days column, read answered by proxycheck.io and proxy undecided. The by-last-seen-day table shows which days still have undecided addresses.

Compare vendor accuracy by state

  1. Open Reports · Location Accuracy (or call GET /accuracy/geo).
  2. Pick the Same addresses pool for a fair comparison, then open the by-state table. Ignore states marked small sample (fewer than 20 tested).

Check the unified tables were refreshed

  1. Open Daily Jobs and read the Unified tables card, or call GET /publish.
  2. last_published_at should be today, after the proxycheck run. The latest run lists its checks and the row count of each table.

Force a fresh proxycheck.io answer for one address

  1. On IP Lookup press Ask proxycheck.io again, or call /lookup/{ip}?refresh=true.

Look up a list and download it

  1. On IP Lookup, choose Many addresses, paste up to 1,000, press Look up, then Download CSV.
  2. For more than 1,000, split the list, or use the Python example above.

Glossary

base table
A production table IP addresses are collected from: raw.raw_tune_clicks (ad clicks) and unified.unified_session_summary (website sessions). Only ever read.
vendor
A source that answers questions about an address: IP2Location DB11, IP2Proxy PX12, FraudLogix, ipinfo.io, ipwho.is, proxycheck.io.
resolved answer
The one answer to use, worked out from every vendor's answer by fixed rules. In ip_resolved and in every lookup.
no conclusion
No vendor answered, vendors disagree, or a flag has nothing confirming it.
backfill
The daily job that asks proxycheck.io about addresses that have no proxycheck.io answer yet: today's and the last 30 days' addresses first, then no-conclusion addresses.
top-up
The 22:00 UTC run that finishes the 50,000 enrichment budget if the morning run stopped early. It never uses the 30,000 kept for lookups.
enrichment
Spending proxycheck.io queries on addresses from the base tables (queue and backfill), as opposed to API lookups.
enrichment coverage
How many addresses have a proxycheck.io answer, a proxy conclusion and an agreed location. The Enrichment Coverage report.
agreement
How often a vendor matches the other vendors. Used on the vendor scorecards.
accuracy
How often a vendor's location matches customers' postal addresses. Used only on the Location Accuracy report.
publish
Refreshing unified.ip_geo and unified.ip_intelligence with checked copies of the ipintel_curated tables, after each proxycheck run that passes.
queue
proxycheck_queue: addresses from new base-table rows that need proxycheck.io, sent before the backfill.
privacy relay
A service (Apple iCloud Private Relay, Cloudflare WARP) that hides a user's address behind a shared one. Shows as VPN.
residential proxy
A home connection used to route other people's traffic, often a compromised device. Shows as proxy on a home ISP.
UTC
Coordinated Universal Time. 07:30 UTC is 00:30 Pacific daylight time and 13:00 India time.
