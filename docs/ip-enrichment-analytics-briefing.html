What we set out to answer

  1. For any IP address the company sees, where is it, and is it a proxy, VPN, Tor exit, datacenter or bot?
  2. Can the IP tables be the company's single lookup source, kept current every day, without touching the production tables they are built from?
  3. Are the addresses from the last 30 days fully enriched?
  4. How accurate is each location vendor, overall and by state, and what should we do when vendors disagree?

How enrichment works

  1. 07:30 UTC, daily load. It finds addresses in the base tables that are not in our tables yet and gives each one IP2Location, IP2Proxy and FraudLogix answers. It records where each address was seen, and rebuilds the resolved answers and the reports.
  2. Queue. Any new or changed address that needs a second opinion goes into a queue: no location, no proxy answer, vendors disagree, or an unconfirmed flag. The API uses the same rule when someone looks up an address.
  3. Right after, proxycheck.io (up to 50,000 a day). Order: queued addresses; then addresses first seen today; then every address seen in the last 30 days without a proxycheck.io answer; then undecided addresses from the last 90 days; then older ones. Each request carries 1,000 addresses, and every query is reserved on a shared counter first, so the daily limit cannot be exceeded.
  4. Merge and check. Answers are merged into the tables. The run passes only if every check passes: no duplicates, no table shrank, one resolved answer per address, every queued address answered, nothing outside the project touched.
  5. Publish. After a passed run, checked copies replace the files behind unified.ip_geo and unified.ip_intelligence, which other teams' APIs read. The previous copy is kept for rollback.
  6. 22:00 UTC top-up. It finishes the 50,000 only if the morning run stopped early. The 30,000 lookup queries are never used for this.

The resolved answer. Vendor rows are kept exactly as each vendor answered. ip_resolved holds one answer per address, worked out by fixed rules. The API applies the same rules, so Athena and the app always agree (1,500 of 1,500 addresses identical in today's check).

Who is right when vendors disagree

These are the same kinds of conflict on the 2,105 customer addresses, counting how often each side matched the customer's real state or city:

  • States differ: ipinfo.io beat IP2Location 80 to 4 and proxycheck.io 53 to 25. ipwho.is beat IP2Location 76 to 6 and proxycheck.io 47 to 25. Where only IP2Location and proxycheck.io answered, IP2Location was right 76 times to proxycheck.io's 42.
  • Same state, cities differ: ipinfo.io was best, then IP2Location, then ipwho.is. Every vendor beat proxycheck.io on city; IP2Location, for example, won 90 to 47.

The fix (live since 16 Sep 10:42 UTC)

  1. Spelling: city names are compared without accents or punctuation. Saint/Mount/Fort count the same as St/Mt/Ft, and a trailing "City" or "Township" is ignored. "St. Louis" now equals "Saint Louis". The old rule compared only the first word, so "New York" wrongly matched "New Hyde Park".
  2. New statuses say how close the vendors are:
    • agreed Same state and city.
    • nearby Same state, within 25 km.
    • same_state Same state, further apart.
    • vendors_disagree States differ.
  3. Evidence-based choice: the answer shown comes from the vendor most often right for that kind of conflict. For state: ipinfo.io, ipwho.is, IP2Location, then proxycheck.io. For city within the agreed state: ipinfo.io, IP2Location, ipwho.is, then proxycheck.io. Before, the choice came from the vendor scorecard.
  4. Tie-breakers: ipinfo.io and ipwho.is now spend their daily requests on the 30-day conflicts first. States-differ comes first, then same-state, and the two vendors take different addresses, so about 1,000 conflicts a day get a third vote. New addresses come after.

Limits and caveats

  • An IP location is not an address. It points to where a connection joins the internet. State is right about 6 times in 10, city about 1 in 7, ZIP rarely. Use it for regional analysis only.
  • The truth set is small and specific. 2,105 customers, and ipinfo.io and ipwho.is were tested on 1,050 of them. The vendor priorities were learned from the same addresses they are scored on, so small differences between vendors (a point or two) should not be over-read.
  • VPN is not fraud. Two in three flagged addresses are privacy relays used by ordinary people.
  • Bot flags come from one vendor. Only FraudLogix answers bot, and none of the 30-day addresses are flagged as bots.
  • Free vendors have limits. Without an ipinfo.io token, requests are limited. The registry notes 50,000 a month with a free token. ipwho.is is listed as "fair use"; its terms for commercial use should be confirmed before relying on it more.
  • Other teams' API. The ip-lookup API reads unified.ip_geo and unified.ip_intelligence but picks its own vendor order: IP2Location for location; FraudLogix, then IP2Proxy for risk. It does not use the resolved answers or the new location statuses, and rarely uses the proxycheck.io rows now in the table.
  • Answers age. proxycheck.io answers are not re-checked yet.

Glossary

base table
A production table addresses are collected from: ad clicks and website sessions. Only ever read.
enrichment
Adding vendor answers (location, proxy/VPN, risk, ISP) to an address.
resolved answer
The one answer per address, worked out from every vendor's answer by fixed rules. Served by Athena and the API alike.
decided / undecided
Decided: proxycheck.io answered, or every vendor says clean. Undecided: no answer, vendors disagree, or an unconfirmed flag.
agreed · nearby · same_state
Location statuses: same state and city; same state within 25 km; same state further apart.
vendors_disagree
For location: no two vendors name the same state.
accuracy
How often a vendor matches the customer's own postal address.
agreement
How often vendors match each other (vendor overview scorecards).
tie-breaker
A third vendor asked when two disagree, so the majority can decide.
publish
Replacing the files behind the two unified tables with a checked copy after each passed run.
privacy relay
A service (Apple iCloud Private Relay, Google One VPN, Cloudflare WARP) that routes ordinary users through shared addresses. Shows as VPN.
